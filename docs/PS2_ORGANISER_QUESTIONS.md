# PS2 questions for the organisers

> Open questions to put to the hackathon organisers. The published scope is only *"Kill Chain Attack Path
> Reconstruction. Turn raw logs into attack stories"* (`PS2_REQUIREMENT_MATRIX.md`). The "today" column states
> what the repository does now, so each answer translates straight into a change, or no change. Record every
> answer with its date and who gave it.

| # | Question | Why it matters | What HALT does today | If the answer differs |
|---|---|---|---|---|
| 1 | **Which raw-log formats must be accepted?** Named products (Entra ID, M365, CloudTrail, Sysmon, Windows Security, Zeek, syslog), and which serialisation (JSON, JSONL, CSV, CEF, plain syslog)? | Each format needs an adapter, and an unmapped one is rejected rather than guessed | Seven adapters: `idp_signin` (JSONL), `idp_audit` (JSON), `mail_trace` (CSV), `api_activity` (JSONL), `cloud_audit` (JSON), `process` (Sysmon EventID 1 as JSONL), `db_audit` (CSV). Unmapped records are rejected, with a reason | Add an adapter per required format; this is the most likely change |
| 2 | **Will an organiser-provided dataset be supplied, and when?** Size, number of sources, time span, and whether it can be shared with the team before judging | Limits (2 MB per file, 5 MB per batch, 20,000 records per file) and adapter coverage must fit it | Two bundled synthetic scenarios plus manual upload | Rehearse on it as soon as it arrives; raise limits only if needed and say so |
| 3 | **Is there a hidden test dataset?** Will it be run by us live, or by the judges offline, and through which interface (UI, API, CLI)? | Decides whether a batch CLI or a documented API call is needed | Upload through the UI, or `POST /api/v1/ps2/ingestions` then `POST /api/v1/ps2/reconstructions` | Add a one-command batch runner if judges run it themselves |
| 4 | **Batch or streaming?** Is reconstruction over a fixed log export acceptable, or must events arrive live? | The engine is a deterministic batch pipeline | Batch only. Same inputs give the same ids and hashes | Streaming would be a new ingestion mode; we would not fake it with a replay loop |
| 5 | **MITRE ATT&CK, the Lockheed Martin Cyber Kill Chain, or both?** | The output vocabulary and the scoring rubric depend on it | ATT&CK Enterprise techniques and tactics, each with a basis (observed, rule-inferred or uncertain). No Lockheed phase mapping | Add a documented tactic-to-phase table, labelled as a mapping |
| 6 | **What exactly is the expected output?** A graph, a narrative, a timeline, a JSON export, a report file, or a named schema? | Decides what is shown first and what is exported | Graph, cited attack story, ATT&CK panel, ranked hypotheses, receipt with content hashes, and an Attack Flow-style JSON export | Add the required export; keep every claim cited |
| 7 | **How will accuracy be measured?** Against whose ground truth? Event-level, edge-level, path-level or root-cause? | Our only measurements are synthetic-on-synthetic | Metrics on the two synthetic scenarios, disclosed as "pipeline behaviour, not real-world accuracy" | Compute their metric on their data. Never present our synthetic figures as theirs |
| 8 | **How will latency be measured?** Wall time end to end, per event, on whose hardware, and at what dataset size? | Our figure is the median of 3 runs on one development machine | `reconstruction_latency_ms` in `services/api/reports/ps2_eval.json`, with that note | Measure on the stated hardware and size; report it with the method |
| 9 | **Pitch duration and format?** Live demo or video, Q&A length, and whether the screen or a projector is used | Sets the script length and the fallback plan | `PS2_FIVE_MINUTE_DEMO.md` is written for 5 minutes, live | Trim to fit, starting with the upload segment |
| 10 | **Submission deadline and contents?** Time zone, repository access, video, slides, and whether a freeze commit is expected | Avoids a late or incomplete submission | Branch `ps2/kill-chain-intelligence`, not merged to `main` | Tag the submitted commit and record it |
| 11 | **Rules on previous work?** May pre-hackathon code (the HALT incident platform) be reused, and how must it be declared? | Much of the shell predates PS2 | Declared in `PS2_ORIGINALITY_AND_DISCLOSURE_PLAN.md`; PS2 work is on its own branch with commit timestamps | Follow their wording for the declaration |
| 12 | **Rules on AI tools?** Are AI coding assistants allowed, and how must their use be disclosed? | Every commit on this branch carries a `Co-Authored-By: Claude` trailer | Disclosed: Claude Code was used as a pair-programmer. No language model runs during reconstruction. HALT-R1, a small bundled anomaly model, contributes one weighted score component, shown in each path's components | Use their disclosure format; never hide the trailers |
