## 3. Rules for the PS2 build

1. PS2 work happens on a new branch with normal commits; timestamps are the evidence of when work was done.
2. Ported PS3 or UI v2 modules are ported in **their own commits** whose messages say "ported from …".
3. Every new dataset, library or asset is added to the ledgers in the same commit.
4. The demo and the deck show the disclosure slide (below) before any metric.
5. No metric is shown unless it was measured by the evaluation harness on the stated dataset.

## 4. Recommended explanation for judges

> "HALT started before this hackathon as our own incident-response prototype: a deterministic engine that ranks
> attack paths, simulates responses and proves the smallest safe containment. For PS2 we are building the part the
> problem asks for and HALT did not have: turning raw logs into the attack story. That means parsing raw security
> logs, resolving users, devices, sessions and tokens across them, inferring each link in the kill chain with
> cited evidence, and evaluating the reconstruction against ground truth. Everything built during the hackathon is
> on its own branch with timestamps. We used Claude Code as an AI pair-programmer; no AI model decides the graph,
> the risk or the response. All data is synthetic and labelled as such."
